# Flutter Agent-Skills Research Report

**Date:** 2026-10-18 · **Scope:** installable agent skills for a Flutter desktop/mobile + Rust-FFI workflow.
**Priorities (in order):** testing → architecture → lint/static analysis → project structure & scalable codebases → performance (desktop/mobile; web unimportant) → Rust+Flutter FFI (flutter_rust_bridge-style) → Dart isolates & concurrency.

**Method.** Everything below is grounded in the vetted research batch supplied with this task: ~390 candidate entries, each carrying its own read/fetch/clone evidence (file sizes, line counts, HTTP statuses, git commits). The leading picks additionally carry live verification — skills.sh pages, GitHub repo metadata, raw SKILL.md fetches, and read-only CLI resolutions (`bunx skills add <source> --list` clones and lists without installing). Nothing was installed; install commands are listed per skill but **not executed**. After merging duplicate candidate ids and removing entries that later proved unresolvable, the catalog holds **275 install recommendations**, ~30 "already covered" duplicates, and ~236 rejections.

---

## 1. Verdict

The ecosystem is **deep exactly where your priorities are strongest and thinnest exactly where they are most specialized**.

- **Testing (#1) is the richest area.** The official `dart-lang/skills` content now sits in a 15-skill suite (mirrored into `flutter/agent-plugins`): unit tests, mocks, coverage, resolve-conflicts, static analysis, FFI assets/ffigen, plus docs/CLI skills. LeanCode ships Patrol skills from the Patrol authors themselves (current in the Patrol 4.10 / `patrol_mcp` 0.2.1 era); and there are at least four credible full-suite doctrines (VGV, zakariaf, 22Teikk, kao273183). Widget/integration/golden/mocking/coverage/flakiness are all covered by multiple substantive options. Caveats: Patrol supports Android/iOS/macOS(alpha) only — no Windows/Linux; `flutter_driver` is deprecated (integration_test is the only in-app option on desktop); `golden_toolkit` is discontinued (alchemist is the live golden harness); Firebase Test Lab is deprecated with shutdown 2027-09-30.
- **A warning that shapes everything else:** the official Flutter and Dart orgs **gutted their topic skills in March–June 2026**. `flutter/agent-plugins` deleted its testing, performance, concurrency, architecture, caching and state skills (commits 094df61, 130378c, 2e24431, a40929a); `dart-lang/skills` cleared almost everything on 2026-04-22. Many skills.sh listings for these (flutter-performance 9.1K installs, flutter-testing-apps, dart-concurrency-isolates…) are **stale ghosts** — uninstallable as named. skills.sh counts are inflated roughly 2x for both repos (89 advertised for `flutter/agent-plugins` where 25 exist plus 6 personal; 31 for `dart-lang/skills` where 15 exist), and even its search API returns dead install commands. Do not install by those ids — resolve `--list` against the source first. The rot continues at the edges: poorgramer-zack's `flutter-isolate` was renamed in place to `running-flutter-isolates` (the old registry id 404s while the GitHub folder kept the old name), and `vartec-chs/Hoplixi` has dropped off the skills.sh index entirely even though its skills still resolve and install from source.
- **Architecture, lint, and structure** are well served by maintained community suites (VGV, zakariaf's 40-skill suite, evanca, gabuldev, ariaramin, plus a complete 23-directory Riverpod reference family from Serverpod). One ecosystem shift: `custom_lint` is archived (2026-03-24); all new lint work goes through the official `analysis_server_plugin` protocol, and `riverpod_lint` 3.1.9+ configures via `analysis_options.yaml` `plugins:` with no pub dev-dependency — custom_lint-authoring skills are maintenance-only for legacy plugins.
- **Rust+Flutter FFI is the thinnest priority.** The official `fzyzcjy/flutter_rust_bridge` repo ships only maintainer-internal skills — 29 `frb-*` directories, every command running `./frb_internal`, which does not exist in your projects (even `frb-fix-merge-conflict` invokes it four times; only its technique transfers). Usable FRB guidance exists only in app repos — Hoplixi (~103KB of references), openmls_dart, onde, telepathy, Genesix, JA_Route — real and deep, but unofficial and partly project-flavored. FRB itself has moved to 2.13.0 with a new native-assets integration backend that no verified skill documents; Rinf is at maintainer risk (the project announced it is looking for a new maintainer, Aug 2026).
- **Desktop-specific skills are scarce** (one true desktop skill found, plus aaronbassett's flutter-core performance plugin and the official-org audit-accessibility skill); desktop coverage otherwise arrives as sections inside performance skills. The platform itself reached GA maturity in Flutter 3.47 — Impeller default on macOS/Windows/Linux, multi-window still experimental. Several strong skills are written in Chinese/Japanese/Korean/Spanish/Portuguese — flagged per entry.

## 6. Gaps — where no good skill exists

1. **An official flutter_rust_bridge usage skill.** The upstream FRB repo ships only maintainer-internal skills (all `./frb_internal`-based, 29 directories), so the best FRB guidance available is unofficial and scattered across app repos (§2.8). Nothing canonical exists for FRB API design + codegen + packaging as one maintained skill — and FRB has since moved to 2.13.0 with a new native-assets integration backend that no verified skill documents; a fresh search surfaced no new FRB skills at all.
2. **FRB-for-multithreading/performance tuning.** Every FRB skill found covers codegen mechanics, patterns, or builds; none focuses on the performance/multithreading exploitation of Rust workers under Flutter (thread pools, streaming backpressure across the bridge, benchmarking Rust tasks from Dart).
3. **Maintained official Flutter/Dart-team performance and concurrency skills.** `flutter/agent-plugins@flutter-performance` was deliberately removed (2e24431) and `dart-lang/skills@dart-concurrency-isolates` was deleted in the April 2026 clear-out; the skills.sh pages for both are stale ghosts. Community skills fill the space (ariaramin, aaronbassett, HoangNguyen, thiennc), but there is no official-maintained option.
4. **Flutter-desktop-specific performance depth.** Exactly one recommended skill has a dedicated desktop performance chapter (ariaramin@flutter-ui-performance-engineering) plus one new plugin (aaronbassett flutter-core); everything else is mobile-first with desktop as an afterthought, and only one true desktop skill exists at all (sqflite-common-ffi-desktop). A house desktop gating standard (high-DPI, live resize, per-OS goldens, xvfb CI, Impeller expectations, fastforge packaging) is author-your-own territory.
5. **Accessibility testing — now partially filled.** The official a11y skill was deliberately removed (a40929a), but VGV's accessibility skill (WCAG 2.2, 6 platforms) and the official-org flutter-intellij audit-accessibility joined the catalog (§2.1), alongside the conalyz lint CLI. A house standard combining semantic tests with the golden overflow/contrast matrix is still worth authoring if the workflow needs one.
6. **`analysis_server_plugin` authoring.** The archived-custom_lint skills teach the dead system; jahfali's plugin has dated pins. A house skill for the new official plugin protocol (rules + quick-fixes) would be first-party territory.
7. **The Riverpod 3 ↔ FFI boundary.** No skill covers the repeated-identical-emission equality gotcha for Rust streams, nor the full native-handle lifecycle (Provider + onDispose + isolate routing) end to end.
8. **Desktop E2E standard.** With Patrol off Windows/Linux, the desktop flow — integration_test matrix, per-OS goldens, xvfb, device-cloud migration off Firebase Test Lab — needs a house skill.

**Fallback:** for these areas, author your own with `bunx skills init` — the vetted batch repeatedly shows that the highest-quality skills in this ecosystem are exactly that: single-purpose, house-style skills extracted from real projects.
