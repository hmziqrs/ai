3 · Issue label states

The label state machine. Machine truth = exactly one pipeline:* label per open issue; only ready is human-set (plan §6.1).

stateDiagram-v2
    direction LR
    state "pipeline:ready — the only human-set label" as ready
    state "pipeline:in-progress" as inp
    state "pipeline:triaged" as tri
    state "pipeline:in-review" as rev
    state "pipeline:failed — terminal" as fail
    state "merged — issue closed, label removed; Merged lives on the board" as merged

    [*] --> ready: human labels the issue
    ready --> inp: claim T2 (gh-ops)
    inp --> tri: triage PASS T3 (Contract stamped and frozen)
    inp --> fail: triage REJECT or quarantine T4, T4-Q
    tri --> rev: PR created T6b
    tri --> fail: fix-cap or unrecoverable T11
    rev --> merged: merge T10 (Closes N auto-close)
    rev --> fail: fix-cap or unrecoverable T11
    fail --> ready: requeue T12 (rule-id + comment)
    merged --> [*]

There is no pipeline:rejected (G13): injection quarantine routes to pipeline:failed with a Quarantined: comment. There is no pipeline:merged label either — merged means the issue closed. The claim order is ready → in-progress → triaged (claim first, then the triage PASS flip), per transitions T2/T3 in plan §6.5.

4 · The Contract through its four checkpoints

The frozen Contract is the single source of truth; it is consumed at four points: plan, PR create, PR edit, pre-merge.

flowchart TD
    C["Contract — frozen at triage: Goal, Requirements, ACs with verifiedBy, Out of scope, Areas. Cached at .zflow/state/contracts/N.json; every dispatch receives the frozen object"]:::contract
    K1["Checkpoint 1 (plan) — task-planner + plan-auditor: union of task acIds equals all ACs; every AC has a task and a verification; one replan allowed"]:::cp
    K2["Checkpoint 2 (PR create) — gh pr create with a script-drafted body: goal, Closes #N, AC table; never model-composed at create time"]:::cp
    K3["Checkpoint 3 (PR edit) — gh pr edit carries the copywriter text; must keep Closes #N; sections map to AC IDs and evidence paths"]:::cp
    K4["Checkpoint 4 (pre-merge) — pr-reviewer cites a diff hunk plus a test path per AC; pr-merger checklist requires Contract satisfied"]:::cp
    M["squash merge — body Closes #N auto-closes the issue"]:::done

    C --> K1 --> K2 --> K3 --> K4 --> M

Legend

  • 1 · Journey — the runtime path one issue takes through the chain. Includes the fix-loop edge (findings above zero → fixer → gates re-run → fresh blind judge) and the escalation edge (cap exceeded → gh-ops escalation issue → pipeline:failed). Orange dashed = script-owned step (no model); blue = engine-run node; purple = main-thread dispatch; red = terminal failure.
  • 2 · Components — the static topology: the thin coordinator and its skill launch tier-pure engine runs (each pinned to a subagent_model) and harness-file dispatches; GitHub holds machine truth (labels) plus the board projection; preview tunnels are best-effort for humans while the local URL stays canonical for machine consumers; state lives in the four on-disk artifacts plus .zflow/state.
  • 3 · Label states — the issue-label state machine, exactly one pipeline:* per open issue; merged is a closed issue, not a label; failed can requeue (T12) after an honest report.
  • 4 · Contract — the frozen Contract (Goal / Requirements / ACs with verifiedBy / Out of scope / Areas) consumed at its four checkpoints: plan, PR create, PR edit, pre-merge.
