Keep all shared application setup, state management (`.manage(...)`), plugin initialization, and `tauri::generate_handler![...]` registration in `src-tauri/src/lib.rs::run()` with `#[cfg_attr(mobile, tauri::mobile_entry_point)]`, leaving `src-tauri/src/main.rs` as a thin passthrough. Commands defined directly in `lib.rs` must not be `pub` (organize public command functions in submodules) and every command name must be unique and registered in a single `generate_handler!` call. Use Tauri v2 APIs: `@tauri-apps/api/core` (`invoke`, `Channel`, `Resource`) and `app.get_webview_window("label")` / `tauri::WebviewWindow` — never v1 `@tauri-apps/api/tauri` or `app.get_window()`. In `async fn` commands, use owned parameter types (`String`, `Vec<u8>`, owned structs) or return `Result<T, E>`, never bare borrowed `&str`/`&[u8]` parameters without `Result`, and never block the main/runtime thread on synchronous I/O. Keep Rust `snake_case` parameters (or explicit `#[tauri::command(rename_all = ...)]`) and `#[serde(tag = ...)]` enum representations aligned with frontend `camelCase` TypeScript wrappers, use `tauri::ipc::Response` for raw binary payloads, and implement `serde::Serialize` on structured command error types (`thiserror`).

Enforce deny-by-default least privilege: grant only the exact `<plugin>:allow-<command>` permissions required, scope filesystem and HTTP rules to specific `$APPDATA`/`$APPCONFIG`/`$RESOURCE` paths or origin patterns, add explicit `deny` rules for secrets/credentials (deny always overrides allow), target capabilities to specific `windows` and `platforms`, and never enable `remote.urls`, broad `$HOME/**` access, `shell:allow-execute`, or new plugins unless the task explicitly requires them. Keep npm and Cargo plugin versions synchronized.
